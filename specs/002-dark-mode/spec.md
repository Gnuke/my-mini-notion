# Feature Specification: 다크 모드

**Feature Branch**: `002-dark-mode`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "다크모드 기능 구현해줘. 모드변경 토글 버튼은 사이드바에 만들고, 이걸 클릭하면 모드가 변경돼야해. 그리고 default는 다크모드로 해줘."

## Clarifications

### Session 2026-07-16

- Q: 모드 전환 토글 버튼을 둘 "사이드바"는 화면의 어느 영역인가? → A: 글 목록
  패널(아이콘 레일 오른쪽의 256px 패널, 검색 입력과 글 목록이 있는 영역).
- Q: 다크 모드의 구체적인 색 값(팔레트)은 어떻게 정하는가? → A: 외부
  레퍼런스인 Notion(실제 노션 앱)의 다크 모드 팔레트를 참조해 Nook의 토큰
  구조에 맞게 이식하고, 확정 값은 `DESIGN.md`에 기록한다.
- Q: 글 목록 패널 안에서 토글 버튼을 어디에 둘 것인가? → A: 패널 상단
  헤더(제목·새 글 버튼이 있는 영역)에 배치한다.
- Q: 로그인 화면에서도 모드를 전환할 수 있어야 하는가? → A: 아니다. 로그인
  화면은 저장된(또는 기본 다크) 모드로 표시만 하고, 전환 버튼은 글 목록
  패널에만 둔다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 사이드바 토글로 모드 전환 (Priority: P1)

사용자가 사이드바에 있는 모드 전환 토글 버튼을 클릭하면, 화면 전체가 즉시
반대 모드(다크 ↔ 라이트)로 바뀐다. 페이지 새로고침이나 별도 조작 없이 클릭
한 번으로 전환이 완료되고, 다시 클릭하면 원래 모드로 돌아온다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 토글 전환 하나만
구현해도 사용자는 원하는 모드로 앱을 쓸 수 있는 완결된 MVP가 된다.

**Independent Test**: 앱 접속 후 사이드바의 토글 버튼을 클릭해 화면 전체의
배경·글자 색이 반대 모드로 바뀌는 것을 확인하고, 재클릭 시 원복되는 것을
확인하면 단독으로 검증 완료.

**Acceptance Scenarios**:

1. **Given** 다크 모드로 표시된 화면, **When** 사이드바의 모드 전환 토글
   버튼을 클릭, **Then** 새로고침 없이 화면 전체(사이드바·글 목록·편집
   영역 포함)가 라이트 모드로 즉시 전환된다
2. **Given** 라이트 모드로 표시된 화면, **When** 토글 버튼을 클릭,
   **Then** 화면 전체가 다크 모드로 즉시 전환된다
3. **Given** 어떤 모드든 표시된 화면, **When** 토글 버튼을 확인,
   **Then** 버튼의 아이콘 또는 라벨로 현재 모드(또는 전환될 모드)를
   알 수 있다

---

### User Story 2 - 기본값은 다크 모드 (Priority: P2)

앱을 처음 방문한 사용자(저장된 모드 선택이 없는 사용자)에게는 다크 모드가
기본으로 표시된다. 로그인 화면을 포함한 모든 화면이 처음부터 다크 모드로
보인다.

**Why this priority**: 사용자가 명시적으로 요구한 기본 동작이다. 토글(P1)이
있어야 의미가 완성되지만, 첫인상을 결정하는 요구사항이므로 우선순위가 높다.

**Independent Test**: 저장된 모드 선택이 없는 상태(예: 브라우저 데이터 초기화
후)로 앱에 접속해 첫 화면이 다크 모드로 표시되는 것을 확인하면 검증 완료.

**Acceptance Scenarios**:

1. **Given** 저장된 모드 선택이 없는 새 방문자, **When** 앱에 접속,
   **Then** 화면이 다크 모드로 표시된다
2. **Given** 저장된 모드 선택이 없는 새 방문자, **When** 로그인 화면에 진입,
   **Then** 로그인 화면도 다크 모드로 표시된다
3. **Given** 운영체제가 라이트 테마로 설정된 기기, **When** 저장된 모드
   선택 없이 앱에 접속, **Then** 운영체제 설정과 무관하게 다크 모드로
   표시된다

---

### User Story 3 - 선택한 모드 유지 (Priority: P3)

사용자가 토글로 선택한 모드는 저장되어, 브라우저를 닫았다가 다시 방문해도
마지막에 선택한 모드가 그대로 적용된다.

**Why this priority**: 없어도 토글과 기본값만으로 기능은 성립하지만, 매번
다시 전환해야 한다면 사용자 경험이 크게 떨어진다.

**Independent Test**: 라이트 모드로 전환한 뒤 브라우저 탭을 닫고 다시 접속해
라이트 모드가 유지되는 것을 확인하면 검증 완료.

**Acceptance Scenarios**:

1. **Given** 사용자가 라이트 모드로 전환한 상태, **When** 브라우저를 닫고
   다시 앱에 접속, **Then** 라이트 모드로 표시된다
2. **Given** 사용자가 라이트 모드에서 다크 모드로 다시 전환한 상태,
   **When** 앱에 재접속, **Then** 다크 모드로 표시된다

---

### Edge Cases

- 저장된 모드 값이 손상되었거나 알 수 없는 값이면 기본값(다크 모드)으로
  동작한다.
- 페이지를 여는 순간 반대 모드가 잠깐 보였다가 바뀌는 깜빡임(플래시)이
  발생하지 않아야 한다.
- 여러 탭을 동시에 연 경우, 이미 열려 있는 다른 탭의 실시간 동기화는
  보장하지 않는다. 새로 로드되는 탭은 마지막 저장된 모드를 따른다.
- 두 모드 모두에서 본문·버튼·안내 문구 등 모든 텍스트가 배경과 충분한
  대비를 유지해 읽을 수 있어야 한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 다크 모드와 라이트 모드, 두 가지 화면 모드를
  제공해야 한다.
- **FR-002**: 사이드바(글 목록 패널)의 상단 헤더에 모드 전환 토글 버튼이
  있어야 하며, 클릭할 때마다 현재 모드가 반대 모드로 전환되어야 한다.
- **FR-003**: 모드 전환은 페이지 새로고침 없이 즉시 화면 전체에 반영되어야
  한다.
- **FR-004**: 저장된 모드 선택이 없는 사용자에게는 다크 모드를 기본으로
  표시해야 한다. 운영체제의 테마 설정은 이 기본값에 영향을 주지 않는다.
- **FR-005**: 사용자가 선택한 모드는 저장되어 재방문 시 그대로 적용되어야
  한다.
- **FR-006**: 저장된 모드 값이 유효하지 않으면 기본값(다크 모드)으로
  동작해야 한다.
- **FR-007**: 모드는 로그인 화면을 포함한 앱의 모든 화면에 일관되게
  적용되어야 한다. 로그인 화면은 현재 모드를 표시만 하며, 전환 수단은
  글 목록 패널의 토글 버튼뿐이다.
- **FR-008**: 토글 버튼은 현재 모드(또는 클릭 시 전환될 모드)를 인지할 수
  있는 표시(아이콘·라벨)를 제공해야 하며, 사용자에게 노출되는 문구는
  한국어여야 한다.
- **FR-009**: 두 모드 모두에서 모든 텍스트와 UI 요소가 배경과 충분한
  대비를 유지해 읽을 수 있어야 한다.

### Key Entities

- **모드 선택(테마 선호)**: 사용자가 마지막으로 선택한 화면 모드
  (다크 또는 라이트). 사용자의 브라우저(기기) 단위로 저장되며, 값이 없으면
  "다크"로 간주한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 저장된 선택이 없는 첫 방문에서 100% 다크 모드로 표시된다.
- **SC-002**: 토글 버튼 클릭 후 1초 이내에 화면 전체가 반대 모드로 전환되며,
  이 과정에서 새로고침이나 추가 조작이 필요 없다.
- **SC-003**: 모드를 전환한 뒤 브라우저를 닫고 재방문해도 마지막 선택 모드가
  100% 유지된다.
- **SC-004**: 페이지 로드 시 반대 모드가 먼저 보였다가 바뀌는 깜빡임이
  발생하지 않는다.
- **SC-005**: 두 모드 모두에서 사용자가 모든 화면의 텍스트를 읽고 주요 과업
  (로그인, 글 작성·편집·삭제)을 완료할 수 있다.

## Assumptions

- 토글 버튼이 들어갈 "사이드바"는 글 목록 패널(256px)이며, 패널 상단
  헤더에 배치한다(Clarifications 참조). 버튼의 모양·크기 등 시각 세부는
  디자인 단계에서 `DESIGN.md` 기준으로 확정한다.
- 모드 선택은 계정이 아니라 브라우저(기기) 단위로 저장된다. 같은 계정이라도
  다른 기기에서는 각자의 선택을 따른다.
- 모드는 다크/라이트 두 가지만 제공한다. "시스템 설정 따르기" 같은 자동
  모드는 범위 밖이다.
- 현재 제품은 라이트 모드 계열의 단일 테마만 있다. 다크 모드의 구체적인
  색 값은 Notion 다크 모드를 레퍼런스로 삼아 디자인 단계에서 정의하고
  `DESIGN.md`에 같은 작업 단위로 기록한다(헌법 원칙 II·V, Clarifications
  참조).
- 이미 열려 있는 다른 탭과의 실시간 모드 동기화는 범위 밖이다.
