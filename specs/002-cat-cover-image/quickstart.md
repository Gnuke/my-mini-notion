# Quickstart: 랜덤 고양이 커버 이미지 — 검증 가이드

**Date**: 2026-07-13 | 관련: [plan.md](./plan.md), [contracts/](./contracts/)

구현이 끝난 뒤(또는 태스크 진행 중) 기능이 실제로 동작함을 증명하는 실행 절차.

## 사전 조건

- Node.js + `npm install` 완료
- 수동 검증 시 인터넷 연결 (cataas.com 접근)

## 1. 자동 테스트 (헌법 완료 게이트)

```powershell
npm test
```

기대 결과: 전체 통과, 에러·경고 없는 무결한 출력. 이 기능이 추가하는 테스트:

- `lib/catCover.test.ts` — `pickRandomCatUrl` 계약([cat-cover-ui.md](./contracts/cat-cover-ui.md) §1)
- `components/CatCover.test.tsx` — 스켈레톤/성공/실패/레이스/콜백
  (모의 fetch는 [cataas-api.md](./contracts/cataas-api.md)의 실측 구조 사용)
- `components/Editor.test.tsx` — CatCover 장착, 기존 커버 UI 부재(FR-010), 이모지 마진 연동

## 2. 수동 검증 시나리오

```powershell
npm run dev
```

브라우저에서 `http://localhost:3000` 접속(미로그인 시 `/login`에서 `구글로 로그인` 클릭).

### 시나리오 A — 커버 표시 (US1 / SC-001)

1. 글 목록에서 아무 글이나 클릭
2. **기대**: 제목 위 전체 폭 밴드(150px)에 즉시 스켈레톤 → 수 초 내 고양이 사진 표시
3. 다른 글로 전환 → **기대**: 새 사진을 다시 불러옴 (같은 사진 고정 아님)
4. 기존 그라데이션 커버가 있던 글(시드 "미니 노션 PRD 정리")도 고양이 커버로 표시되고,
   `커버 추가`/`커버 변경` 버튼이 어디에도 없음 (FR-010)

### 시나리오 B — 스켈레톤 로딩 (US2 / SC-002, SC-003)

1. DevTools → Network 탭 → Throttling을 `Slow 3G`로 설정
2. 다른 글 클릭
3. **기대**: 커버 자리에 맥동하는 회색 스켈레톤(스피너 아님), 로딩 중에도 제목·본문
   편집 가능
4. 이미지가 나타나는 순간 제목 입력창이 위아래로 밀리지 않음 (레이아웃 이동 0)

### 시나리오 C — 실패 시 조용한 숨김 (US3 / SC-004)

1. DevTools → Network 탭 → `Offline` 설정
2. 다른 글 클릭
3. **기대**: 잠시 스켈레톤 후 커버 영역이 사라지고 제목부터 정상 표시. 깨진 이미지·
   무한 스켈레톤·오류 배너 없음. 제목·본문 편집 정상 동작
4. `Online` 복귀 후 글 전환 → 커버 다시 표시

### 시나리오 D — 빠른 연속 전환 (FR-008)

1. Throttling `Slow 3G` 상태에서 글 A → B → C를 빠르게 연속 클릭
2. **기대**: 마지막 글 C의 커버(또는 스켈레톤)만 표시. 이전 글의 이미지가 뒤늦게
   나타나 덮어쓰지 않음

### 시나리오 E — 빈 상태 (FR-007)

1. 모든 글을 삭제(탑바 `삭제` → 확인)해 빈 상태 화면 표시
2. **기대**: 커버 이미지·스켈레톤이 어디에도 없음
