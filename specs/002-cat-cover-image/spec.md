# Feature Specification: 랜덤 고양이 커버 이미지

**Feature Branch**: `002-cat-cover-image`

**Created**: 2026-07-13

**Status**: Draft

**Input**: User description: "제목 입력창 위에 커버 이미지를 놓자. 이미지는 오픈 api인 랜덤 고양이 사진 api를 사용할거야. api endpoint는 https://cataas.com/api/cats?tags=cute 야. api가 로딩되는 동안에는 로딩 스피너 대신 스켈레톤 ui로 처리해줘."

## Clarifications

### Session 2026-07-13

- Q: 같은 글을 다시 열면 같은 커버 사진이 보여야 하는가? → A: 아니다(A안).
  커버는 저장하지 않으며, 글을 열거나 전환할 때마다 새 랜덤 사진을 불러온다.
- Q: 커버 불러오기 실패 시 어떻게 처리하는가? → A: 조용히 숨긴다(A안).
  커버 영역 자체를 제거하고 제목부터 정상 표시하며, 별도 오류 UI는 두지 않는다.
- Q: 기존 그라데이션 커버 기능(커버 추가·변경·삭제)과의 관계는? → A: 전면
  교체(A안). 기존 그라데이션 커버 기능을 제거하고, 모든 글의 커버를 랜덤 고양이
  사진으로 통일한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 글을 열면 커버 이미지가 보인다 (Priority: P1)

사용자가 편집할 글을 열면, 제목 입력창 바로 위에 귀여운 고양이 사진이 커버
이미지로 표시된다. 사진은 외부 랜덤 고양이 사진 제공처에서 가져오므로 글을
열 때마다 다른 사진이 나올 수 있다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 커버 이미지가 표시되는
것만으로 사용자에게 완결된 가치를 주는 MVP가 된다.

**Independent Test**: 글을 하나 열고 제목 입력창 위에 고양이 사진이 표시되는지,
다른 글로 전환하거나 다시 열었을 때 커버가 새로 불러와지는지 확인하면 단독으로
검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 글 목록에 글이 있을 때, **When** 사용자가 글 하나를 열면,
   **Then** 제목 입력창 위 커버 영역에 고양이 사진이 표시된다.
2. **Given** 글 A가 열려 있을 때, **When** 사용자가 글 B로 전환하면,
   **Then** 커버 이미지가 새로 불러와져 표시된다.
3. **Given** 커버 이미지가 표시된 상태일 때, **When** 사용자가 제목이나 본문을
   편집하면, **Then** 커버 이미지는 편집을 방해하지 않고 그대로 유지된다.

---

### User Story 2 - 로딩 중에는 스켈레톤 UI가 보인다 (Priority: P2)

커버 이미지를 불러오는 동안, 커버가 표시될 자리에 로딩 스피너가 아닌 스켈레톤
UI가 표시된다. 이미지가 준비되면 스켈레톤이 이미지로 자연스럽게 교체되며,
그 과정에서 제목 입력창과 본문의 위치가 움직이지 않는다.

**Why this priority**: 외부 제공처의 응답 속도는 통제할 수 없으므로 로딩 상태
경험이 곧 기능의 체감 품질을 결정한다. 다만 P1(커버 표시)이 없으면 의미가
없으므로 P2다.

**Independent Test**: 네트워크를 느리게 설정한 뒤 글을 열어, 커버 자리에
스켈레톤이 표시되는지(스피너가 아닌지), 이미지 표시 시점에 제목 입력창이
아래위로 밀리지 않는지 확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 커버 이미지를 아직 불러오는 중일 때, **When** 사용자가 편집
   화면을 보면, **Then** 커버 자리에 커버와 같은 크기의 스켈레톤 UI가 표시되고
   로딩 스피너는 표시되지 않는다.
2. **Given** 스켈레톤이 표시된 상태일 때, **When** 이미지가 준비되면,
   **Then** 스켈레톤이 이미지로 교체되고 제목 입력창의 위치는 변하지 않는다.
3. **Given** 커버를 불러오는 중일 때, **When** 사용자가 다른 글로 전환하면,
   **Then** 이전 글의 이미지가 아닌 새로 불러온 이미지(로딩 중에는 스켈레톤)가
   표시된다.

---

### User Story 3 - 불러오기 실패 시에도 편집은 정상 동작한다 (Priority: P3)

외부 제공처 장애나 네트워크 오류로 커버 이미지를 불러오지 못해도, 사용자는
제목과 본문을 평소처럼 편집할 수 있다. 실패한 커버 영역은 조용히 사라지며
깨진 이미지나 오류 화면으로 편집을 방해하지 않는다.

**Why this priority**: 외부 의존성이 있는 기능의 안전망이다. 발생 빈도는 낮지만
없으면 핵심 흐름(글 편집)까지 망가뜨릴 수 있다.

**Independent Test**: 네트워크를 차단한 상태에서 글을 열어, 스켈레톤이 무한히
남거나 깨진 이미지가 보이지 않고 커버 영역이 정리되는지, 제목·본문 편집이
정상 동작하는지 확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 외부 이미지 제공처에 접근할 수 없을 때, **When** 사용자가 글을
   열면, **Then** 커버 영역은 표시되지 않고(스켈레톤·깨진 이미지 없이) 제목
   입력창부터 정상 표시된다.
2. **Given** 커버 불러오기가 실패한 상태일 때, **When** 사용자가 제목과 본문을
   편집하면, **Then** 편집이 평소와 동일하게 동작한다.

---

### Edge Cases

- 외부 제공처 응답이 매우 느린 경우: 스켈레톤이 그동안 계속 표시되며, 편집은
  로딩과 무관하게 즉시 가능하다.
- 목록 응답은 성공했지만 사진 목록이 비어 있는 경우: 실패와 동일하게 커버
  영역을 표시하지 않는다.
- 사진 정보는 받았지만 이미지 자체를 불러오지 못하는 경우: 깨진 이미지를
  보여주지 않고 실패와 동일하게 처리한다.
- 커버 로딩 중 다른 글로 빠르게 연속 전환하는 경우: 마지막에 연 글의 커버만
  표시되고, 이전 요청 결과가 뒤늦게 도착해 화면을 덮어쓰지 않는다.
- 선택된 글이 없어 빈 상태 화면이 보이는 경우: 커버 이미지도 스켈레톤도
  표시하지 않는다.
- 기존에 그라데이션 커버가 저장돼 있던 글을 여는 경우: 저장된 값과 무관하게
  랜덤 고양이 커버가 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 글이 열려 있을 때, 편집 화면의 제목 입력창 바로 위에 커버 이미지
  영역을 표시해야 한다.
- **FR-002**: 커버 이미지는 외부 오픈 API가 제공하는 랜덤 고양이 사진 중
  "귀여운(cute)" 태그가 붙은 사진을 사용해야 한다.
- **FR-003**: 글을 열거나 다른 글로 전환할 때마다 커버 이미지를 새로 불러온다.
  이미지는 글에 저장되지 않는 표시용 값이다.
- **FR-004**: 커버 이미지를 불러오는 동안에는 커버 영역에 스켈레톤 UI를
  표시해야 하며, 로딩 스피너는 사용하지 않는다.
- **FR-005**: 스켈레톤은 커버 이미지와 동일한 크기를 차지해, 이미지로 교체될 때
  제목 입력창과 본문의 위치가 이동하지 않아야 한다.
- **FR-006**: 커버 이미지를 불러오지 못하면(제공처 장애, 네트워크 오류, 빈
  결과, 이미지 로드 실패 포함) 커버 영역을 표시하지 않으며, 제목·본문 편집은
  평소와 동일하게 동작해야 한다.
- **FR-007**: 선택된 글이 없는 빈 상태 화면에서는 커버 이미지와 스켈레톤을
  표시하지 않는다.
- **FR-008**: 커버 로딩 중 다른 글로 전환하면 이전 글의 불러오기 결과가 새 글의
  커버를 덮어쓰지 않아야 한다.
- **FR-009**: 커버와 관련해 사용자에게 노출되는 문자열(대체 텍스트 등)이 있다면
  한국어로 작성해야 한다.
- **FR-010**: 기존 그라데이션 커버 기능(커버 추가·커버 변경·삭제 버튼과 색상
  선택 UI)은 제거하고, 커버를 랜덤 고양이 사진으로 일원화해야 한다. 글에 저장돼
  있던 기존 커버 값은 더 이상 사용하지 않는다.

### Key Entities

- **커버 이미지**: 외부 제공처에서 가져온 랜덤 고양이 사진. 편집 화면 상단을
  꾸미는 표시용 값이며, 글 데이터에 저장하거나 다른 화면에서 재사용하지 않는다.
- **글(포스트)**: 제목과 본문을 가진 기존 문서 단위. 기존에 글마다 저장하던
  그라데이션 커버 값은 더 이상 사용하지 않으며, 새 커버는 저장하지 않으므로
  저장 구조에 새 항목이 추가되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 글을 열면 커버 영역이 즉시(스켈레톤 형태로) 나타나고, 정상적인
  네트워크 환경에서 5초 이내에 고양이 사진이 표시된다.
- **SC-002**: 커버 로딩 상태에서 로딩 스피너가 표시되는 경우가 0건이다. 로딩
  표현은 항상 스켈레톤 UI다.
- **SC-003**: 스켈레톤이 이미지로 교체되는 순간 제목 입력창의 세로 위치 변화가
  없다(레이아웃 이동 0).
- **SC-004**: 외부 이미지 제공처에 장애가 있어도 사용자는 제목·본문 편집을
  평소와 동일하게 100% 수행할 수 있다.

## Assumptions

- 커버 이미지는 모든 글에 자동으로 표시된다. 기존 그라데이션 커버 선택 기능은
  이 기능으로 대체되어 제거되며, 사용자가 커버를 켜고 끄거나 직접 선택·변경하는
  기능은 이번 범위 밖이다.
- 커버 이미지는 표시용이며 글에 저장하지 않는다. 같은 글이라도 열 때마다 다른
  사진이 표시될 수 있다.
- 이미지 제공처는 사용자가 지정한 오픈 API를 사용한다: cataas.com의 랜덤 고양이
  사진 API, 엔드포인트 `https://cataas.com/api/cats?tags=cute` (외부 의존성).
- 불러오기 실패 시 커버 영역을 숨기는 조용한 실패 처리를 따른다. 재시도 버튼,
  오류 배너 등 별도 오류 UI는 범위 밖이다.
- 커버의 높이·모서리·스켈레톤의 시각 스타일(색상·모션 등)은 디자인 단계에서
  `DESIGN.md` 기준으로 확정한다.
