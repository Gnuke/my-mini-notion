# Feature Specification: 마이페이지 자기소개

**Feature Branch**: `002-profile-introduction`

**Created**: 2026-07-16

**Status**: Draft

**Input**: User description: "자기소개 기능을 구현해줘. 마이페이지에 현재 별명 기능만 존재해. 추가로 자기소개도 등록/수정/조회 가능하도록 만들어줘. DB에 introduction 컬럼 만들었으니까 연결하면 돼. 내가 만든 DB는 변경하면 안돼."

## Clarifications

### Session 2026-07-16

- Q: 자기소개 저장은 어떤 방식으로 동작해야 하는가? → A: 기존 "변경 사항
  저장" 버튼 하나로 별명과 자기소개를 함께 저장한다(전용 버튼·자동 저장 없음).
- Q: 자기소개 최대 길이는 몇 자로 하는가? → A: 500자로 확정한다(저장소가
  아닌 화면 차원의 제한).
- Q: 마이페이지 진입 시 자기소개를 불러오지 못하면 어떻게 동작하는가? → A:
  한국어 오류 안내를 표시한다. 미등록 상태(입력 유도 문구)와 구분되어야 하며,
  사용자는 새로고침 등으로 재시도할 수 있다.
- Q: 자기소개를 불러오는 동안 화면은 어떻게 보이는가? → A: 기존 마이페이지
  로딩 방식과 동일하게 자기소개까지 준비된 뒤 화면을 표시한다. 입력 도중
  뒤늦게 도착한 저장본이 입력 내용을 덮어쓰는 일은 없어야 한다.
- Q: 저장소에 이미 500자를 초과하는 자기소개가 있으면 어떻게 처리하는가? →
  A: 조회 시에는 전체를 그대로 표시하고, 500자 제한은 수정해 저장할 때만
  적용한다(임의 잘라내기로 인한 데이터 유실 금지).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 자기소개 등록과 확인 (Priority: P1)

사용자가 마이페이지의 자기소개 입력란에 자신을 소개하는 글을 입력하고 저장하면,
저장이 완료되었다는 확인 표시가 나타난다. 이후 화면을 새로고침하거나 다른
화면에 갔다가 마이페이지로 돌아와도 저장한 자기소개가 그대로 표시된다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 등록과 조회가 함께
동작해야 자기소개가 "남는다"는 완결된 가치를 제공하므로, 이 스토리 하나만
구현해도 MVP가 된다.

**Independent Test**: 자기소개가 없는 상태에서 마이페이지를 열어 자기소개를
입력·저장하고, 새로고침 후 다시 마이페이지에 들어가 같은 내용이 표시되는지
확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 자기소개가 등록되지 않은 상태로 마이페이지가 열려 있을 때,
   **When** 자기소개 입력란에 "안녕하세요, 기록을 좋아합니다."를 입력하고
   "변경 사항 저장" 버튼을 누르면, **Then** 저장 완료를 알리는 한국어 확인
   표시가 나타난다.
2. **Given** 자기소개를 저장한 뒤, **When** 화면을 새로고침하거나 다른 화면에
   갔다가 마이페이지로 돌아오면, **Then** 저장한 자기소개가 입력란에 그대로
   표시된다.
3. **Given** 자기소개가 등록되지 않은 상태일 때, **When** 마이페이지를 열면,
   **Then** 자기소개 입력란에 입력을 유도하는 한국어 안내 문구가 표시된다.

---

### User Story 2 - 자기소개 수정 (Priority: P2)

사용자가 이미 등록한 자기소개를 마이페이지에서 고쳐 쓰고 저장하면, 이후에는
수정된 내용이 표시된다. 내용을 모두 지우고 저장하면 자기소개가 없는 상태로
돌아간다.

**Why this priority**: 자기소개는 시간이 지나며 바뀌는 정보라 수정이 필수지만,
등록(P1)이 없으면 수정할 대상 자체가 없으므로 P2다.

**Independent Test**: 자기소개가 저장된 상태를 만들어 두고, 내용을 수정해
저장한 뒤 마이페이지를 다시 열어 수정본이 표시되는지, 전부 지우고 저장하면
미등록 상태의 안내 문구로 돌아가는지 확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 자기소개 "첫 소개"가 저장되어 있을 때, **When** 내용을 "고친
   소개"로 수정하고 저장하면, **Then** 이후 마이페이지에서 "고친 소개"가
   표시된다.
2. **Given** 자기소개가 저장되어 있을 때, **When** 내용을 모두 지우고
   저장하면, **Then** 자기소개는 미등록 상태가 되어 입력을 유도하는 안내
   문구가 다시 표시된다.

---

### User Story 3 - 저장·불러오기 실패 시 안내와 입력 보존 (Priority: P3)

자기소개 저장이나 불러오기가 실패하면(저장소에 일시적으로 접근할 수 없는 경우
등) 사용자에게 한국어로 실패를 알린다. 저장 실패 시 입력한 내용은 입력란에
그대로 남아 다시 저장을 시도할 수 있고, 불러오기 실패는 미등록 상태와 구분되어
표시된다.

**Why this priority**: 자기소개는 화면 밖 저장소에 보관되므로 실패 가능성이
있다. 다만 정상 흐름(P1·P2)이 동작한 뒤에 의미가 있는 보강이므로 P3다.

**Independent Test**: 저장소에 접근할 수 없는 상황을 만들어 저장과 마이페이지
진입을 각각 시도하고, 오류 안내가 표시되며 입력 내용이 사라지지 않는지, 빈
상태 안내와 구분되는지 확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 저장소에 접근할 수 없는 상태에서, **When** 자기소개 저장을
   시도하면, **Then** 한국어 오류 안내가 표시되고 입력한 내용은 입력란에
   그대로 유지된다.
2. **Given** 저장 실패를 겪은 뒤 저장소가 복구되었을 때, **When** 다시 저장을
   시도하면, **Then** 저장 완료 확인 표시가 나타나고 내용이 정상적으로
   유지된다.
3. **Given** 자기소개가 저장되어 있으나 저장소에 접근할 수 없는 상태에서,
   **When** 마이페이지를 열면, **Then** 자기소개 영역에 한국어 오류 안내가
   표시되며, 미등록 상태의 입력 유도 문구와 오인되지 않는다.

---

### Edge Cases

- 공백·줄바꿈만 입력하고 저장하면 자기소개가 없는 것으로 간주해 미등록 상태와
  동일하게 처리한다.
- 자기소개는 최대 길이(500자)를 초과해 입력할 수 없으며, 사용자가 제한을 알 수
  있어야 한다.
- 저장소에 이미 500자를 초과하는 자기소개가 있으면 조회 시 전체를 그대로
  표시한다. 제한은 수정해 저장할 때만 적용하며, 임의로 잘라 데이터가 유실되면
  안 된다.
- 자기소개를 불러오는 동안에는 기존 마이페이지 로딩 방식과 동일하게 준비된 뒤
  화면을 표시하므로, 입력 도중 저장본이 뒤늦게 도착해 내용을 덮어쓰는 상황이
  발생하지 않는다.
- 줄바꿈이 포함된 여러 줄 자기소개는 저장·조회 시 줄바꿈이 그대로 유지된다.
- 이모지가 포함된 자기소개도 입력한 그대로 저장·표시된다.
- 저장하지 않고 페이지를 벗어나면 변경분은 반영되지 않으며, 다음 방문 시 마지막
  저장본이 표시된다.
- 자기소개를 불러오지 못한 상태는 미등록 상태와 구분해 오류로 안내한다. 저장된
  내용이 있는지 알 수 없는 상태에서 사용자가 모르고 덮어쓰지 않게 하기 위함이다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 마이페이지에 자기소개 입력 영역을 제공해야 하며, 여러 줄 입력이
  가능해야 한다.
- **FR-002**: 자기소개 저장은 마이페이지의 기존 "변경 사항 저장" 버튼 하나로
  이루어지며(전용 저장 버튼·자동 저장 없음), 저장 시 자기소개는 사용자가 미리
  준비해 둔 기존 프로필 저장소의 자기소개 항목에 저장되어야 한다. 이 기능을
  위해 기존 저장소의 구조(항목 추가·변경·삭제)를 어떤 방식으로도 바꿔서는 안
  된다.
- **FR-003**: 마이페이지에 들어오면 저장된 자기소개를 불러와 표시해야 하며,
  새로고침·재방문 후에도 동일하게 유지되어야 한다. 화면은 자기소개까지 준비된
  뒤에 표시하고(기존 마이페이지 로딩 방식과 동일), 사용자가 입력을 시작한
  뒤에 뒤늦게 도착한 저장본이 입력 내용을 덮어써서는 안 된다.
- **FR-004**: 자기소개가 등록되지 않은 경우 입력을 유도하는 한국어 안내 문구를
  표시해야 한다.
- **FR-005**: 기존 자기소개를 수정하고 저장하면 수정된 내용으로 갱신되어야
  한다. 내용을 모두 지우거나 공백·줄바꿈만 남기고 저장하면 미등록 상태로
  돌아간다.
- **FR-006**: 저장이 성공하면 한국어 확인 표시를 보여야 하며, 마이페이지의
  기존 저장 확인 방식과 일관되어야 한다.
- **FR-007**: 저장이 실패하면 한국어 오류 안내를 표시하고, 사용자가 입력한
  내용을 잃지 않아야 한다.
- **FR-008**: 자기소개는 최대 500자까지 입력할 수 있으며, 제한이 있다는 사실을
  사용자가 알 수 있어야 한다. 제한은 수정·저장 시에만 적용한다. 저장소에 이미
  500자를 초과하는 자기소개가 있으면 조회 시 전체를 그대로 표시하고, 잘라서
  보여주거나 잘라서 저장해서는 안 된다.
- **FR-009**: 별명·이메일·프로필 이미지 등 마이페이지의 기존 기능 동작은
  변경되지 않아야 한다.
- **FR-010**: 마이페이지 진입 시 자기소개를 불러오지 못하면 한국어 오류 안내를
  표시해야 하며, 이 상태는 미등록 상태(입력 유도 문구)와 구분되어야 한다.
  사용자는 새로고침 등으로 다시 시도할 수 있다.

### Key Entities

- **프로필**: 사용자 1인의 별명·이메일·프로필 이미지로 구성된 기존 정보에
  자기소개가 추가된다. 자기소개는 있어도 되고 없어도 되는 선택 항목이며, 여러
  줄 텍스트다. 저장처는 사용자가 미리 준비해 둔 기존 프로필 저장소이고, 그
  구조는 이 기능으로 인해 변경되지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 별도 안내 없이 마이페이지에서 자기소개 등록을 1분 이내에
  완료할 수 있다.
- **SC-002**: 저장된 자기소개가 새로고침·재방문 후에도 100% 유지된다(유실
  0건).
- **SC-003**: 저장 시도의 결과(성공 또는 실패)를 사용자가 체감 지연 없이 즉시
  확인할 수 있다.
- **SC-004**: 자기소개 기능 추가 이후에도 기존 마이페이지 기능(별명 변경,
  프로필 이미지 변경)에 회귀가 0건이다.

## Assumptions

- 자기소개의 저장처는 사용자가 이미 만들어 둔 프로필 저장소의 introduction
  항목이며, 이 기능은 해당 저장소의 구조를 어떤 방식으로도 변경하지 않는다
  (사용자가 명시한 제약).
- 현재 앱의 로그인은 프로토타입용 모의 인증이므로, 자기소개는 미리 준비된 단일
  사용자 프로필 1건에 연결된다. 실제 인증 도입 시에는 로그인한 사용자 본인의
  프로필로 연결되는 것을 전제로 한다.
- 자기소개 최대 길이는 500자다(Clarifications에서 확정). 글자 수는 본문 글자
  수 카운터 기능(001)과 동일하게 사용자가 하나의 글자로 인지하는 단위로 세며,
  공백과 줄바꿈도 포함한다.
- 자기소개의 등록·수정·조회 화면은 마이페이지 하나로 한정한다. 다른 화면(글
  목록 등)에 자기소개를 노출하는 것은 이번 범위 밖이다.
- 입력란의 위치·크기·색상 등 시각 스타일은 디자인 단계에서 `DESIGN.md` 기준으로
  확정한다.
