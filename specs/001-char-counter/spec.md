# Feature Specification: 본문 글자 수 카운터

**Feature Branch**: `001-char-counter`

**Created**: 2026-07-10

**Status**: Draft

**Input**: User description: "내용 입력칸에 내용 입력하면 글자 수 계산하는 기능 만들어줘. 우측 하단에 만들 예정이야."

## Clarifications

### Session 2026-07-10

- Q: 글자 수 표시는 긴 글을 스크롤할 때 어떻게 동작하는가? → A: 에디터 화면
  우측 하단에 고정(플로팅)되어 스크롤 위치와 무관하게 항상 보인다.
- Q: 글자 수 계산 단위는 무엇인가? → A: 사용자가 하나의 글자로 인지하는 단위로
  센다. 조합 이모지(👨‍👩‍👧)·국기 이모지도 각 1자다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 입력 중 실시간 글자 수 확인 (Priority: P1)

사용자가 글의 본문 입력칸에 내용을 입력하면, 편집 화면 우측 하단에 현재 본문의
글자 수가 실시간으로 표시된다. 사용자는 글을 쓰는 동안 별도 조작 없이 지금까지
쓴 분량을 즉시 확인할 수 있다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 이 스토리 하나만 구현해도
사용자에게 완결된 가치를 제공하는 MVP가 된다.

**Independent Test**: 글을 하나 열고 본문에 텍스트를 입력·삭제·붙여넣기하면서
우측 하단 표시가 올바른 글자 수로 즉시 갱신되는지 확인하면 단독으로 검증할 수
있다.

**Acceptance Scenarios**:

1. **Given** 본문이 비어 있는 글이 열려 있을 때, **When** 사용자가 본문에
   "안녕하세요"를 입력하면, **Then** 우측 하단 글자 수 표시가 "5자"로 갱신된다.
2. **Given** 본문에 텍스트가 있는 글이 열려 있을 때, **When** 사용자가 텍스트
   일부를 삭제하면, **Then** 글자 수가 줄어든 값으로 즉시 갱신된다.
3. **Given** 글이 열려 있을 때, **When** 사용자가 클립보드의 긴 텍스트를
   본문에 붙여넣으면, **Then** 붙여넣은 내용을 포함한 전체 글자 수가 즉시
   표시된다.
4. **Given** 본문이 비어 있는 글이 열려 있을 때, **When** 사용자가 아무것도
   입력하지 않으면, **Then** 글자 수는 "0자"로 표시된다.

---

### User Story 2 - 글 전환 시 글자 수 갱신 (Priority: P2)

사용자가 목록에서 다른 글을 선택하면, 글자 수 표시가 새로 열린 글의 본문
기준으로 즉시 바뀐다.

**Why this priority**: 여러 글을 오가며 작업하는 사용자에게 잘못된(이전 글의)
글자 수가 남아 있으면 기능을 신뢰할 수 없게 된다. 다만 P1이 없으면 의미가
없으므로 P2다.

**Independent Test**: 본문 길이가 다른 글 두 개를 준비하고, 글을 전환할 때마다
표시가 각 글의 본문 글자 수와 일치하는지 확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 본문이 "가나다"(3자)인 글 A와 본문이 비어 있는 글 B가 있을 때,
   **When** 글 A를 보다가 글 B로 전환하면, **Then** 글자 수 표시가 "3자"에서
   "0자"로 바뀐다.

---

### User Story 3 - 글이 선택되지 않은 상태에서는 표시하지 않음 (Priority: P3)

선택된 글이 없어 빈 상태 화면이 보일 때는 글자 수 표시가 나타나지 않는다.

**Why this priority**: 셀 대상(본문)이 없는 화면에 카운터가 남아 있으면
혼란을 주지만, 핵심 흐름(글 작성)에는 영향이 없어 우선순위가 가장 낮다.

**Independent Test**: 선택된 글이 없는 빈 상태 화면을 띄우고 글자 수 표시가
화면에 없는지 확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 선택된 글이 없어 빈 상태 화면이 표시될 때, **When** 사용자가
   화면을 확인하면, **Then** 글자 수 표시가 화면에 존재하지 않는다.

---

### Edge Cases

- 공백·줄바꿈만 입력된 본문: 공백과 줄바꿈도 각각 1자로 세어 표시한다.
- 이모지가 포함된 본문: 일반 이모지(😀)는 물론, 여러 문자가 조합된 이모지
  (👨‍👩‍👧)와 국기 이모지도 사용자 인지와 같게 각 1자로 센다.
- 매우 긴 본문(수만 자)을 입력하거나 붙여넣어도 입력 반응성이 유지되어야 한다.
- 본문 전체를 선택해 한 번에 삭제하면 "0자"로 즉시 갱신된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 현재 열려 있는 글의 본문 입력칸에 입력된 텍스트의 글자
  수를 계산해야 한다. 제목 입력칸의 텍스트는 포함하지 않는다.
- **FR-002**: 글자 수는 입력·삭제·붙여넣기 등 본문이 변경되는 즉시 갱신되어야
  한다.
- **FR-003**: 글자 수 표시는 편집 화면 우측 하단에 고정(플로팅)되어 스크롤
  위치와 무관하게 항상 보여야 한다.
- **FR-004**: 글자 수는 사용자가 하나의 글자로 인지하는 단위로 센다. 공백과
  줄바꿈도 각 1자로 포함하며, 여러 문자가 조합된 이모지(예: 👨‍👩‍👧)와 국기
  이모지도 각 1자로 센다.
- **FR-005**: 글자 수 표시 문구는 한국어로 한다(예: "128자").
- **FR-006**: 본문이 비어 있으면 "0자"로 표시한다.
- **FR-007**: 선택된 글이 없는 빈 상태 화면에서는 글자 수를 표시하지 않는다.
- **FR-008**: 다른 글로 전환하면 글자 수가 새로 열린 글의 본문 기준으로 즉시
  갱신되어야 한다.

### Key Entities

- **글(포스트)**: 제목과 본문을 가진 기존 문서 단위. 글자 수는 본문 텍스트에서
  파생되어 화면에 표시되는 값이며, 별도로 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 본문을 변경하면 체감 지연 없이(즉시) 글자 수가 갱신된다.
- **SC-002**: 한글·영문·숫자·공백·줄바꿈이 섞인 임의의 본문에 대해 표시되는
  글자 수가 FR-004의 계산 규칙과 100% 일치한다.
- **SC-003**: 수만 자 분량의 본문에서도 입력 중 체감할 수 있는 지연이 발생하지
  않는다.
- **SC-004**: 사용자가 추가 조작(클릭·메뉴 진입 등) 없이 글을 쓰는 화면에서
  바로 글자 수를 확인할 수 있다.

## Assumptions

- "내용 입력칸"은 편집 화면의 본문 입력 영역을 의미하며, 제목 입력칸은 계산
  대상이 아니다.
- "우측 하단"은 본문을 편집하는 화면(에디터 영역)의 우측 하단에 고정된 플로팅
  표시를 의미한다(스크롤과 무관하게 항상 표시). 정확한 위치·크기·색상 등 시각
  스타일은 디자인 단계에서 `DESIGN.md` 기준으로 확정한다.
- 글자 수는 공백과 줄바꿈을 포함해 세는 가장 단순한 규칙을 따른다(단어 수,
  공백 제외 글자 수 등 추가 지표는 범위 밖).
- 글자 수는 표시용 파생 값이며 저장하거나 다른 화면에서 재사용하지 않는다.
