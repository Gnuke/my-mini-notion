# Feature Specification: 사이드바 접기/펼치기

**Created**: 2026-07-16

**Status**: Draft

## Clarifications

### Session 2026-07-16

- Q: 접기/펼치기 대상이 되는 "사이드바"는 어느 부분인가? → A: 왼쪽 전체
  (아이콘 레일 + 글 목록 패널, 316px)를 함께 접는다.
- Q: 접힌 상태의 화면 형태와 다시 펼치는 방법은? → A: 접히면 왼쪽 가장자리에
  좁은 세로 스트립이 남고, 그 안의 같은 토글 버튼을 클릭해 다시 펼친다.
- Q: 새로고침·재방문 시 접힘 상태를 유지(저장)해야 하는가? → A: 저장하지
  않는다. 항상 펼침 상태로 시작한다.
- Q: 마이 페이지에서도 접기/펼치기를 제공해야 하는가? → A: 업무 화면에서만
  제공한다. 마이 페이지는 지금처럼 아이콘 레일을 항상 표시한다.
- Q: 접힘/펼침 전환에 슬라이드 모션이 있어야 하는가? → A: 모션 없음.
  클릭 즉시 전환된다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버튼 클릭으로 사이드바 접기/펼치기 (Priority: P1)

사용자가 사이드바에 있는 토글 버튼을 클릭하면 사이드바 전체(아이콘 레일 +
글 목록 패널)가 접혀 글 편집 영역이 넓어진다. 같은 버튼을 다시 클릭하면
사이드바가 원래대로 펼쳐진다. 사용자는 글쓰기에 집중하고 싶을 때 사이드바를 치우고, 다른 글로
이동하고 싶을 때 다시 꺼낼 수 있다.

**Why this priority**: 이 기능의 핵심 가치 그 자체다. 이 스토리 하나만
구현해도 사용자에게 완결된 가치를 제공하는 MVP가 된다.

**Independent Test**: 업무 화면에서 토글 버튼을 클릭해 사이드바가 접히는지,
다시 클릭해 펼쳐지는지, 접힌 동안에도 버튼이 계속 보이고 클릭 가능한지
확인하면 단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사이드바가 펼쳐진 업무 화면에서, **When** 사용자가 토글 버튼을
   클릭하면, **Then** 사이드바가 접혀 왼쪽 가장자리에 좁은 세로 스트립만
   남고, 편집 영역이 그만큼 넓어진다.
2. **Given** 사이드바가 접힌 상태에서, **When** 사용자가 스트립 안의 토글
   버튼을 다시 클릭하면, **Then** 사이드바가 다시 펼쳐져 글 목록·검색 등
   원래 내용이 그대로 표시된다.
3. **Given** 사이드바가 접힌 상태에서, **When** 사용자가 화면을 확인하면,
   **Then** 왼쪽 가장자리 스트립 안에 다시 펼칠 수 있는 토글 버튼이 계속
   보이고 클릭 가능하다.
4. **Given** 사이드바가 펼쳐진 상태에서, **When** 사용자가 토글 버튼을 여러 번
   연속으로 클릭하면, **Then** 클릭 횟수에 따라 접힘/펼침 상태가 정확히
   번갈아 전환되고 화면이 어긋나지 않는다.

---

### User Story 2 - 접힌 상태에서도 작업 연속성 유지 (Priority: P2)

사이드바를 접어도 열려 있던 글의 편집은 그대로 계속할 수 있고, 다시 펼치면
접기 전의 목록 상태(선택된 글, 입력해 둔 검색어)가 그대로 유지된다.

**Why this priority**: 접기 기능의 목적이 "글쓰기 집중"이므로, 접는 순간
편집이 끊기거나 펼쳤을 때 상태가 초기화되면 기능을 신뢰할 수 없게 된다.
다만 P1이 없으면 의미가 없으므로 P2다.

**Independent Test**: 글을 선택하고 검색어를 입력한 뒤 사이드바를 접고,
본문을 이어서 편집한 다음 다시 펼쳐서 선택·검색어가 유지되는지 확인하면
단독으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 글이 열려 있는 상태에서 사이드바를 접었을 때, **When** 사용자가
   제목이나 본문을 편집하면, **Then** 편집과 자동 저장이 평소와 동일하게
   동작한다.
2. **Given** 검색어를 입력하고 특정 글을 선택한 뒤 사이드바를 접었을 때,
   **When** 사이드바를 다시 펼치면, **Then** 입력해 둔 검색어와 선택된 글
   표시가 접기 전과 동일하게 유지된다.
3. **Given** 사이드바가 접힌 상태에서, **When** 사용자가 화면을 확인하면,
   **Then** 글 목록·검색·명령 입력과 홈·새 글·마이 페이지 등 사이드바에 속한
   요소는 보이지 않고, 사이드바를 다시 펼치면 평소처럼 사용할 수 있다.

---

### Edge Cases

- 사이드바가 접힌 상태에서 글을 삭제하면: 기존 규칙대로 남은 글이 자동
  선택되거나 빈 상태 화면이 표시되며, 사이드바는 접힌 상태를 유지한다.
- 사이드바가 접힌 상태에서 선택된 글이 없으면: 빈 상태 화면이 스트립을
  제외한 편집 영역 전체에 표시되고, 스트립 안의 토글 버튼은 계속 접근
  가능하다.
- 토글 버튼을 빠르게 연타해도 상태가 꼬이지 않고 마지막 클릭 기준의
  접힘/펼침 상태가 된다.
- 브라우저를 새로고침하면 사이드바는 기본 상태(펼침)로 표시된다(상태 영속은
  범위 밖 — Assumptions 참고).
- 사이드바가 접힌 상태에서 마이 페이지로 이동했다가 업무 화면으로 돌아오면:
  사이드바는 기본 상태(펼침)로 표시되어도 무방하다(화면 이동 간 상태 유지
  요구 없음). 마이 페이지 자체는 접기 기능 없이 항상 레일을 표시한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 사이드바에 접기/펼치기 토글 버튼을 하나 제공해야
  한다. 접기 대상 "사이드바"는 업무 화면 왼쪽 영역 전체 — 아이콘 레일(홈·
  새 글·아바타)과 글 목록 패널 — 를 말한다.
- **FR-002**: 사이드바가 펼쳐진 상태에서 토글 버튼을 클릭하면 사이드바가
  접혀 왼쪽 가장자리에 좁은 세로 스트립만 남고, 편집 영역(에디터 또는 빈
  상태 화면)이 스트립을 제외한 나머지 폭 전체를 차지해야 한다.
- **FR-003**: 사이드바가 접힌 상태에서 토글 버튼을 클릭하면 사이드바가 다시
  펼쳐져야 한다.
- **FR-004**: 토글 버튼은 접힘/펼침 어느 상태에서도 화면에 보이고 클릭
  가능해야 한다. 접힌 상태에서는 왼쪽 가장자리 스트립 안에 같은 버튼이
  남는다.
- **FR-005**: 접기/펼치기는 화면 표시만 바꾸며, 글 데이터·선택된 글·입력해 둔
  검색어에 영향을 주지 않아야 한다. 다시 펼치면 접기 전 상태가 그대로
  표시된다.
- **FR-006**: 사이드바가 접힌 상태에서도 열려 있는 글의 편집(제목·본문·
  이모지·커버)과 자동 저장은 평소와 동일하게 동작해야 한다. 사이드바에 속한
  기능(글 목록·검색·명령 입력, 홈·새 글·마이 페이지 이동)은 접힌 동안
  숨겨지며, 다시 펼치면 동일하게 사용할 수 있어야 한다.
- **FR-007**: 토글 버튼은 현재 상태에서 어떤 동작을 하는지 알 수 있는 한국어
  설명(예: 접기/펼치기)을 제공해야 하며, 사용자에게 노출되는 모든 문구는
  한국어로 한다.
- **FR-008**: 업무 화면에 처음 진입하면 사이드바는 펼쳐진 상태가 기본이다.
- **FR-009**: 접기/펼치기 기능은 업무 화면(글 목록과 편집 영역이 있는
  화면)에서만 제공한다. 마이 페이지에서는 아이콘 레일이 항상 표시되며 토글
  버튼을 제공하지 않는다.
- **FR-010**: 접힘/펼침 전환은 모션(애니메이션) 없이 즉시 완료되어야 한다.

### Key Entities

- **사이드바 표시 상태**: 접힘/펼침 두 가지 값을 갖는 화면 상태. 표시에만
  사용하는 값이며 글 데이터와 무관하고, 별도로 저장하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 클릭 한 번으로 사이드바를 접거나 펼 수 있다(추가 메뉴
  진입·설정 불필요).
- **SC-002**: 토글 시 전환 모션 없이 즉시 화면 전환이 완료된다.
- **SC-003**: 사이드바를 접었다가 다시 펼쳤을 때 글 목록·선택된 글·검색어가
  접기 전과 100% 동일하게 유지된다.
- **SC-004**: 사이드바를 접으면 편집 영역의 가로 폭이 접기 전보다 넓어진다.
- **SC-005**: 접힘/펼침을 여러 번 반복해도(예: 연속 10회) 화면 깨짐이나 상태
  불일치가 발생하지 않는다.

## Assumptions

- "사이드바"는 업무 화면 왼쪽 영역 전체 — 아이콘 레일(홈·새 글·아바타)과
  글 목록 패널(내 글 목록·검색·명령 입력) — 를 의미하며, 접을 때 함께 접힌다
  (Clarifications Session 2026-07-16에서 확정).
- 접힌 상태에서는 아이콘 레일·글 목록 등 사이드바 내용이 화면에서 숨겨지고,
  왼쪽 가장자리에 좁은 세로 스트립이 남아 그 안의 토글 버튼으로 다시 펼친다
  (Clarifications Session 2026-07-16에서 확정). 스트립의 정확한 폭·버튼
  모양은 디자인 단계에서 확정한다.
- 접힘/펼침 상태는 저장하지 않는다. 새로고침하거나 다시 방문하면 기본
  상태(펼침)로 시작한다(세션 간 영속은 이번 범위 밖 — Clarifications
  Session 2026-07-16에서 확정).
- 토글 버튼의 정확한 위치·모양(아이콘/문구)과 스트립 폭 등 시각 스타일은
  디자인 단계에서 `DESIGN.md` 기준으로 확정한다. 전환 모션은 두지 않는 것으로
  확정했다(Clarifications Session 2026-07-16). 현재 `DESIGN.md`에 사이드바
  접기 관련 명세는 없으므로(미구현 기능) 디자인 단계에서 명세를 추가하고 같은
  작업 단위로 문서를 갱신한다.
- 반응형 분기(좁은 화면에서 자동 접힘 등)는 기존 앱과 동일하게 범위 밖이다.
