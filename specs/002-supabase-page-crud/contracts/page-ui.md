# Contract: UI 상태 & 문자열 (page-ui)

**Feature**: 002-supabase-page-crud | **Date**: 2026-07-16

사용자에게 보이는 상태·문구의 계약. 모든 신규 문자열은 한국어(원칙 III).
스타일 값은 DESIGN.md의 기존 토큰·기록된 리터럴 패턴만 조합하며, 구현과 같은
작업 단위로 DESIGN.md에 반영한다(원칙 II·V).

## 1. 글 목록 (PostList)

### 1.1 구조 변경

- 행에서 **이모지 열 제거**(FR-009) — 행은 제목 + 메타 줄만.
- 메타 줄: `{rel(created)} · {본문 미리보기 40자}` (기존 `updated` →
  `created`). 정렬: `created` 내림차순.
- 검색·명령 입력·`＋ 새 글` 버튼: 변경 없음.

### 1.2 로딩 상태 [신규] (FR-011)

- 조건: 스토어 `loading === true`.
- 위치·스타일: 기존 목록 빈 상태와 동일 블록
  (`padding: 22px 12px; text-align: center; color: var(--text-tertiary);
  font-size: 13px; line-height: 1.6`).
- 문구: `불러오는 중…`
- 로딩 중에는 빈 상태 문구·목록 행·검색 결과 없음 문구를 렌더하지 않는다.

### 1.3 조회 실패 상태 [신규] (FR-007)

- 조건: `loadError === true` (loading 아님).
- 같은 블록 스타일로 문구 + 버튼:
  - 문구: `글을 불러오지 못했어요.`
  - 버튼: `다시 시도` — `＋ 새 글` 버튼과 동일 스타일(`height: 28px;
    padding: 0 11px; border-radius: var(--radius-sm); background:
    var(--accent) / hover var(--accent-hover); color: #fff; font-size: 13px;
    font-weight: 500`), `margin-top: 10px`. 클릭 → `retry()`.

### 1.4 새 글 생성 실패 [신규] (FR-007)

- 조건: `createFailed === true`.
- 위치: 구분선 아래, 목록 영역 위 한 줄
  (`padding: 0 12px 8px; font-size: 12px; color: var(--text-danger)`).
- 문구: `새 글을 만들지 못했어요.`
- 해제: 다음 `newPost()` 성공 시.

### 1.5 빈 상태 (기존 유지)

- 로딩·오류가 아니고 글이 0개일 때만: `아직 글이 없어요.` + `'＋ 새 글'로
  시작하세요.` (기존 문구·스타일 그대로)

## 2. 에디터 (Editor)

### 2.1 제거되는 요소 (FR-009)

- 이모지 표시(58px)·이모지 피커 팝오버 전체.
- 커버 밴드(150px)·커버 피커·`커버 변경`/`삭제`(커버)/`🖼 커버 추가` 버튼 전체.
- 제거 후 제목 `<input>`이 본문 컬럼의 첫 요소가 되며, 기존 이모지의 상단
  리터럴(`margin-top: 12px`)을 제목이 승계한다(새 임의 값 없음).

### 2.2 작성자 메타 줄 (변경)

- `{닉네임} · {rel(created)} 작성됨` — 라벨 `편집됨` → `작성됨`,
  기준 시각 `updated` → `created`. 스타일 변경 없음.

### 2.3 저장 표시 상태 머신 (변경 — FR-012)

위치·기본 스타일은 기존 탑바 저장 표시(`font-size: 12px;
color: var(--text-tertiary)`) 유지.

| 상태 | 조건 | 문구 | 색 |
| --- | --- | --- | --- |
| 평상시 | 기본 | `자동 저장` | `var(--text-tertiary)` |
| 저장됨 | 서버 저장 **성공 직후** 1.5초 (`saved`) | `저장됨 ✓` | `var(--text-tertiary)` |
| 저장 실패 | `saveFailed` (update 실패) | `저장 실패` | `var(--text-danger)` |
| 삭제 실패 | `saveFailed` (delete 실패) | `삭제 실패` | `var(--text-danger)` |

- 입력 직후에는 `저장됨 ✓`를 표시하지 않는다(낙관적 표시 금지 — FR-012).
- 실패 상태에서도 편집 중 내용은 화면에 유지된다(FR-007).
- 실패 표시는 다음 서버 저장 성공 시 평상시로 복귀.

### 2.4 삭제 확인 (기존 유지 + 서버 연동)

- 팝오버 문구·스타일 기존 그대로 (`이 글을 삭제할까요?` / `되돌릴 수
  없어요.` / `취소` / `삭제`).
- `삭제` 확정 → 서버 delete **성공 후** 목록에서 제거·다음 글 선택. 실패 시
  글 유지 + 저장 표시 영역에 `삭제 실패`.

## 3. 신규/변경 UI 문자열 전수 목록 (전부 한국어 — 원칙 III)

| 문자열 | 위치 | 구분 |
| --- | --- | --- |
| `불러오는 중…` | 목록 로딩 | 신규 |
| `글을 불러오지 못했어요.` | 목록 조회 실패 | 신규 |
| `다시 시도` | 목록 조회 실패 버튼 | 신규 |
| `새 글을 만들지 못했어요.` | 목록 생성 실패 줄 | 신규 |
| `저장 실패` | 탑바 저장 표시 | 신규 |
| `삭제 실패` | 탑바 저장 표시 | 신규 |
| `{rel} 작성됨` | 에디터 메타 줄 | 변경(`편집됨` → `작성됨`) |

삭제되는 문자열: `커버 변경`, `삭제`(커버 버튼), `🖼 커버 추가`.
